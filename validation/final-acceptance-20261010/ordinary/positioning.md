# 内部定位与信息主线

本稿服务于使用支持 Skill 的 Agent 客户端、已有目标客户与产品事实、需要英文产品内容的独立开发者或小型产品团队。情境是产品已经能做一些明确的事，但首次接触的人仍难以看懂工作流，团队需要把已有判断转成一个可核验的首页首屏。目标是帮助读者理解这份 Skill 并完成一次实际采用，不把内容制作等同于市场选择、发布或效果验证。这个读者定义是本次采用任务的假设，尚无客户研究或付费证据支持，不宜写成“我们的客户都……”。[P1, P3, P7]

英文一句话：**Global Positioning & Growth Content is a Markdown Skill for turning your existing product facts and target-reader brief into positioning and English product content inside a Skill-capable agent client.**

核心主张是“把已有产品事实与目标读者，转成工作流清楚、主张能回到证据的产品内容”。它的机制是可复用的范围与证据边界，以及按任务读取的方法文件，由用户客户端中的 Agent 执行。公开表达必须同时让人知道这是 Markdown 方法 Skill，用户需要自己的客户端、模型和产品输入。它不提供独立编辑器、托管服务或模型额度。[P1, P2]

辅助主张可以分为三个角度。对第一次采用，安装单元是独立的 `skills/global-growth-content`，可以只做一次首页首屏，无需先安装其他阶段的 Skill，也无需购买 API 或安装 npm/pip 包来使用这份 Markdown。对持续表达工作，它可覆盖定位、页面、开发者 README、搜索内容以及社媒或 UGC brief；按任务读取参考方法，不要求一次生成所有内容。对证据不足的产品，它仍可写出基于能力的初稿，但效果、客户数量、转化率等主张需要另外提供证据。[P1, P2, P6]

差异应落在工作方式上：直接给普通模型一个提示，对简单的一次性改写仍然合理；这份 Skill 让团队复用内容范围、证据边界和按需方法文件。不能据此推导更好的产出、更高转化或更短耗时。适用条件是用户已经知道服务谁、有可授权使用的产品事实，并愿意在成稿后核查主张。若用户要它决定市场、自动发布、投放广告、销售或验证实验，本次采用不匹配其范围。[P1, P3]

可复用的信息主线是“输入已有判断 → 使用 Skill 整理表达 → 核查成稿 → 决定自己的下一步”。先呈现读者的实际场景：产品能做什么已经明确，但首页仍让陌生人难以理解。随后解释输入：目标读者、产品类型、工作流、证据和本次目标。再解释输出：有类别、读者情境、机制、价值和可行 CTA 的完整首屏。最后说明核查：每项事实回到产品资料，缺证据的效果承诺删除或留作内部假设。CTA 指向公开仓库与 README，首次使用任务是一个首屏；目前没有付款流程。[P1, P6, P7]

证明材料应严格分层。源材料支持它是 Markdown 方法 Skill、独立安装单元含 10 个文件、提供相应内容任务方法、采用 MIT 许可。2026-10-10 的记录证明完整包曾复制到临时隔离技能目录，入口和内部链接检查无错误。这只证明那次复制与检查，不能证明所有客户端自动发现或最新方法已经在公开仓库上线。材料注明本地方法版本 `6b57209`、远端版本 `994b27b`，待发布文案不能说最新版本已上线。[P2, P4, P7]

读者可能问“为什么不用一个提示？”可答：若任务简单，可以继续直接写提示；若想复用任务范围和证据边界，可试一次 Skill 的首屏任务并自己评估。“安装后就能用吗？”可答：需要支持 Skill 的客户端，把完整安装单元放到客户端实际配置的目录，并确认它能发现该 Skill；隔离检查没有验证自动发现。“没有客户效果数据还能写吗？”可答：可以写能力与工作流，不能写未经证实的节省时间或转化提升。“会自动发到 LinkedIn 吗？”可答：它生成内容，不执行发布。[P1–P6]

禁止公开宣称的内容包括：有客户付费或评价、已有采用人数、胜过普通模型或其他 Skill、确定提升内容质量、节省某比例时间、提高转化、所有客户端通用安装路径、一键自动发布、内置模型额度、最新方法已经公开上线，以及把历史合成运行次数作为客户效果证明。[P4, P5, P7]

内部状态说明：本轮没有市场访谈、模型效果比较或商业实验；读者假设未经市场确认。共同材料没有截图、成片或可展示的客户端录屏，视频与轮播需要实际制作。本轮可行下一步是按 README 获取公开包、确认客户端发现情况，再用这份 Skill 的授权产品资料完成一个首屏，逐条核对；这不等于批准发布。
