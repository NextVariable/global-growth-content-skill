# 内部定位与可复用信息主线

本次定位对象是 Global Positioning & Growth Content（global-growth-content），读者固定为使用支持 Skill 的 Agent 客户端、已经有目标客户与产品事实、需要英文产品内容的独立开发者或小型团队。典型情境是产品已有功能和使用方式，但首页、README 与社媒对“这是什么、怎么开始”表达不一致；团队希望把同一份授权 brief 转成可检查的英文首屏，再扩展相关内容。这是本轮采用任务的工作假设，并非客户访谈或购买意愿结论。目的先让读者理解并尝试一个真实任务；实际下一步是阅读公开仓库 README、获取独立安装目录，然后在自己的兼容客户端发起一次首屏任务。[P1, P2, P6, P7]

## 英文一句话

Global Positioning & Growth Content is a Markdown Skill for turning your existing product facts and audience decisions into positioning, product pages, READMEs, and related content in a Skill-capable agent client.

## 核心主张与信息主线

核心主张是“把已知产品与已选读者连接成能检查的产品表达”。读者提供目标、工作流、事实、证据和禁止宣称项；Skill 引导 Agent 先连接客户任务、产品机制、条件和证明，再写成符合本次目的的完整内容。它可以帮助组织表达，用户仍需检查稿件是否忠于资料。公开表达宜用“turn your brief into a product introduction you can check against its sources”，不可改成“保证写出更高转化页面”。[P1, P3, P6]

辅助主张一是范围可复用：同一套 Markdown 方法涵盖定位、页面、开发者采用及平台改写，方法文件按任务读取，首个任务可以只做首屏，不强制整包。辅助主张二是采用单元清楚：skills/global-growth-content 是完整的独立安装目录，包含入口、六份方法、模板、客户端元数据和 MIT 许可，共十文件；无需先装其他增长 Skill，也无需为了使用 Markdown 方法安装 pip/npm 包。辅助主张三是主张与证据分开：缺少效果数据仍可写基于能力的初稿，但客户数、节省比例、转化提升不能从生成过程推导出来。[P1, P2, P5]

对外信息顺序：先说这是一份在现有 Agent 客户端中使用的 Markdown Skill；再给已有 brief 到可核验首屏的具体任务；随后解释输入和按需方法；最后给查看 README 与第一次调用的下一步。不要先展示“五部分体系”或一串功能名，把读者寻找入口的任务变成体系学习。

## 差异、取舍与适用条件

差异在于把通用提示中的范围、证据纪律与按需方法整理成可重复使用的文件单元。这是实现方式差异，尚无证据证明优于普通模型或读者自建提示。若读者只需改一句标语，直接提示模型仍是合理方案；当同一产品需要多份内容沿用相同事实与边界时，这份 Skill 值得评估。是否适合自己的工作流，应通过一次有真实输入的任务判断，而非靠所谓“更智能”的标签。[P1, P2; known_alternatives]

必要条件是用户已有目标客户或愿意明确给定读者、拥有可使用的产品事实，并使用能加载 Skill 的 Agent 客户端。Skill 自身不提供模型、额度、独立编辑器或发布系统。使用者负责输入与审阅，技术评估者需要核对客户端技能目录、发现机制、模型和资料权限；小团队不因此被假定已有采购流程。客户资料留在用户项目内，不能作为安装包中的通用素材。[P1–P3, P5]

## 可用证明

能力证明来自入口及模块：方法明确要求恢复任务、核对机制与来源、交付完整正文、分离公开稿与内部假设。包结构证明来自十文件清单。2026-10-10 的实际隔离复制和链接检查未发现错误，支持“这个单元可以被完整复制且内部链接通过检查”；它不能证明所有客户端都能自动发现或生成效果更好。公开仓库与 README 是已有入口，MIT 是许可事实；本地方法版本为 6b57209，远端材料记录为 994b27b，本轮不得把本地新方法描述为已经上线。[P1, P2, P4, P7]

## 疑虑回应

“我已有提示词，为什么要换？”如果一次性提示已够用，可以继续使用；这里提供可检查、可维护的方法文件，适合试验是否能减少不同稿件之间的事实漂移，但不能承诺实际减少多少返工。

“需要先做完整市场研究吗？”不需要强制运行其他 Skill。已有目标与产品事实可以直接作为文字 brief 输入；市场或购买行为有空白时要显式标成假设，不能由这份内容 Skill 代替研究。[P1–P3, P6]

“装上就能自动生成或发布吗？”加载由客户端决定，任务还需要用户明确发起并提供资料。Skill 生成内容，不执行部署、社媒发布、外联、投放、销售或实验。[P2–P5]

“会带来额外费用吗？”安装的是 MIT 许可 Markdown 文件，没有本 Skill 的付款入口；客户端模型与工具由所用客户端提供，费用和额度要按该客户端的安排判断。不要将“无需本 Skill 的付费 API”夸大为“所有使用完全免费”。[P2, P5, P7]

## 禁止宣称与内部假设

禁止宣称已有付费客户、客户评价、客户 logo、节省百分比、转化率、写作质量必然更好、胜过普通模型或其他 Skill、全客户端自动发现、自动发布、已经制作好视频或截图、当前远端就是 6b57209。历史合成运行不能充当真实用户效果。[P4, P7; capability_proof_limits]

待验证的是固定读者是否需要这种文件化方法、首屏任务是否是合适的首次采用路径，以及本轮稿件是否足够清楚。这些只影响本次表达判断，不提供未来产品变更方案或市场重选。本文及后续五份稿件是内容交付，尚未部署、发布或测量增长结果。
