# README 帮助合格用户完成第一次任务

先读授权仓库的实际入口、环境要求、版本和文档，识别个人试用、团队采用和采购角色。首屏解释产品、适用任务、区别与限制；用真实截图/可复现演示支持机制。安装与最小使用示例应能把输入转成可观察输出；文档、示例、集成、社区、商业服务仅链接真实可用入口。没有入口给待配置项，不编造 URL。

核验时记录具体命令、工作目录、依赖/运行环境、退出状态和关键输出；隔离运行，避免覆盖用户文件或使用真实凭据。先检查脚本的副作用，不运行不可信代码或不必要联网安装。涉及付费服务、外部写入或缺少环境时说明阻塞，仍交付可读 README，并明确哪些步骤未运行。静态阅读、成功安装、最小示例运行、真实服务集成是不同验证状态。

示例只能使用产品确有的 API/参数；复制文档不能证明能跑。遇到失败先确定环境、路径、参数或产品问题，修正示例并重跑；如果需修改产品代码，记录问题并交回相应开发工作，不在文案任务里默默扩大范围。列关键限制与常见失败点，如支持格式、网络依赖、数据写入、权限、大小/环境约束，按实际资料写。

个人采用关注最小任务与本地限制，团队关注集成、权限、数据路径、维护和兼容，采购关注商业授权与服务条件，缺少信息不补企业能力。stars 可以描述公开社区关注且要有日期，不作为客户数量、效果或商业成功证明，不用“先 star 才给说明”替代采用体验。


布局按首次采用的阻力安排：一句任务说明与关键区别之后，尽早展示最小运行路径；界面型工具可先放真实截图，命令行工具可先放真实输入和输出。将复杂配置、架构、扩展与商业服务放在初次任务之后，必需的权限或费用条件必须提前。功能按用户任务说明，而非堆技术名词；结构图仅在有助理解数据或集成路径时提供，不为显得完整添加没有实现的接口。


一句介绍优先让读者识别工具和首个用途，按需要补受众或关键差异。名称不熟悉时先说明类别，不以“强大、革命性”开场。合成例：源码只提供CSV列选择工具，介绍“Select the columns you need from a CSV file”比“Powerful data productivity toolkit”更符合真实能力。下面紧接实际文件输入、正确命令和输出；网络服务、配置或费用若是必需条件，必须在命令之前交代。字数和命令数不是硬标准，最短路径也不能省略必需步骤。
